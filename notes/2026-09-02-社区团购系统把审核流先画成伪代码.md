# 社区团购系统：把审核流先画成伪代码

> 用伪代码钉死创建/审核状态机
> 示例系统：社区团购系统
> tags: 伪代码, 系统设计

## 先把模块钉死

毕设最常见的翻车不是某段 CRUD 写不出来，而是边界没钉死。下面用「社区团购系统」把核心用例拆成可对照的伪代码。

建议栈：Spring Boot + Vue + MySQL。

### 核心用例：创建并审核

`	ext
function SubmitRequest(user, payload):
    validate payload
    rec = save(status=PENDING)
    notify reviewer
    return rec.id

function ReviewRequest(admin, rec_id, pass):
    rec = load(rec_id)
    if rec.status != PENDING: reject
    rec.status = APPROVED if pass else REJECTED
    write audit log
    notify user
`

### 最小数据表

| 表 | 关键字段 | 说明 |
|---|---|---|
| user | id, role | 学生 / 管理员 |
| request | id, user_id, status, payload | PENDING / APPROVED / REJECTED |
| audit_log | request_id, actor, action | 审核轨迹 |

### 自检清单

1. 状态机只有这三种，不要一上来做工作流引擎。
2. 审核接口必须校验角色，不能只藏按钮。
3. 演示准备一条待审、一条已通过、一条驳回。
